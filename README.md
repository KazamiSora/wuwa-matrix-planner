# 鸣潮终焉矩阵血线排布 V0.2.2

本项目由GPT-6.1 Sol全程Coding

《鸣潮》终焉矩阵队伍和血线的小工具。选好角色、填入队伍分数后，就能看到每队从哪只 Boss 的多少血开始、打到哪里结束，方便调整出场顺序。

## 下载和运行

在 [Releases](https://github.com/KazamiSora/wuwa-matrix-planner/releases) 下载 `WuwaMatrixPlanner-v0.2.2-win-x64.zip`，完整解压后双击 **终焉矩阵血线排布.exe**。

便携版适用于 Windows 10/11 x64，已附带运行时和本地头像，无需另装 Node.js 或 Python。窗口优先使用本机 Edge，其次 Chrome；都没有时会打开默认浏览器。

关闭窗口后，程序还会留在系统托盘。双击托盘图标可以重新打开，右键选择“退出软件”即可完全退出。

## 怎么用

可以在“排布方案”中保存和切换多套排布，每套分别保留队伍、分数、体力版本和目标标记。“复制排布”会生成一个独立副本，“复制配置”可以把当前方案的 JSON 复制出来。导入 JSON 会新增一套方案，保留已有方案。软件内另放了一套“示例B · 椿丹白先手”，方便比较不同出场顺序。

“我的队伍”右侧的“一览表”可以查看当前排布的全部队伍，按出场顺序列出队名、三名角色和分数，待填分数的队伍也会显示。一览表用于集中查看，编辑阵容和分数仍在队伍设置中进行。

不需要的方案可以删除。删除前会明确提示永久删除、无法撤回；选择“导出后删除”会先下载 JSON，再等你确认备份已保存后删除。删除最后一套时会新建空白排布。

新建排布时可以选择终焉矩阵 S2-3 或 S2-4。队伍排布 JSON 分别保存 `matrixSeason`（矩阵期数）、`matrixVersion`（版本名称）、`towerId`（关卡）和 `staminaSeason`（体力规则），旧配置会补上对应字段。

S2-4 的 Boss 顺序为飞廉之猩、达妮娅、无冠者、辛吉勒姆、矩阵奇藏，来源为 [Nanoka 的 S2-4 页面](https://ww.nanoka.cc/newtower/18)。血量和分数暂按 S2-3 相同轮次、相同出场位次沿用，R1—R15 均可排布，界面里会标注“暂定”；这部分还不是 S2-4 实测数据。

1. 先选好“体力期数”，再新建队伍，选择三名角色。可以直接填写分数，也可以先留空，按 5000 分预览排布。队名默认取角色首字，例如“相里要、吟霖、卡提希娅”会生成“相吟卡”，也可以自己改名。
2. 队伍会按顺序排在同一条轴上，第一队从 0 分开始，后续队伍首尾相接。拖动色条可以换顺序，双击可以编辑。
3. 鼠标停在色条上，可以查看阵容、起止位置、Boss 剩余百分比和剩余分数。下方详情卡也会显示这些信息。
4. 在“目标总分”里输入分数，点“定位并标记”，就能跳到对应位置。标记会和排布一起保存。
5. “显示至”可以选择 R1—R15。“全部血线”只适配当前所选范围，例如选到 R10 就显示到 R10；“全部队伍”适配已排队伍，也可以手动缩放、横向滚动。
6. 点击 Boss 血线，可以查看抗性图标、特殊性质、总血量和总分数。填入“剩余血量”百分比，会实时显示这只 Boss 从满血到当前位置的已获取分数和剩余分数，不包含前面 Boss 的累计分数。矩阵奇藏只有在剩余 0% 时才计入 1000 分击杀奖励。

未填分数的队伍会以斜纹色条显示，长度暂按 5000 分计算。实际分数保持待填，补分后会重新计算长度。前面还有待填队伍时，后续队伍的起止位置也会标为“预览”。

队伍设置旁的“撤回”“恢复”最多保留最近两次队伍删除操作，各排布方案分别记录。撤回会找回被删队伍的阵容、分数和位置，保留其他队伍后续的修改。这套记录与快捷组队里的草稿撤回分开；删除整个排布方案仍是永久删除。队伍删除记录在当前页面会话中保留，刷新页面后会清空。

分数是自己填写的预期得分，程序不会自动计算队伍伤害或推荐最优配队。

### 快捷组队

想先把阵容排好，可以点“快捷组队”连续选人：第 1—3 人一队，第 4—6 人下一队，依次接在已有队伍后面。

快捷组队窗口已加大，电脑上会随屏幕宽度显示 10、12 或 14 列头像。1440×1050 的窗口下可以完整看到 60 个头像；普通队伍编辑仍使用紧凑的选人窗口。

选人窗口左侧会显示已有队伍和本次组队进度，列出角色头像与姓名，方便对照阵容。角色剩余体力放在头像左上角，多体力标记放在右下角。

手机上按 4 列显示头像，队伍一览放在上方的滚动区域，确认加入的按钮保持可见。

快捷组队不用填队名和分数。队名自动生成，加入后直接在轴上按每队 5000 分显示预览，也会列在“待填分数”区域。双击队伍即可补上实际分数。最后一队不足三人时，需要补齐再加入。

“撤回”“恢复”和“重置”只处理本次快捷选人，不影响已经排好的队伍。重置也可以撤回。支持 Ctrl+Z、Ctrl+Y，以及 Ctrl+Shift+Z。

### 角色体力

目前按以下规则限制上阵次数：

- 普通角色：1 体，可进一队。
- 守岸人、维里奈、白芷、卜灵、莫宁、穗穗：基础 2 体，可进两队。
- 终焉矩阵S2-3（S2第三阶段）临时加成：琳奈 +1 体。
- 终焉矩阵S2-4（S2第四阶段）临时加成：洛瑟菈 +1 体。

选人界面会显示剩余体力，编辑队伍时不会重复扣本队的名额。漂泊者的不同属性共用体力，同一队里也不能重复选同一角色。

切换体力版本前会检查已有阵容。例如两队都用了琳奈时，切换到 S2-4 会显示冲突清单，列出使用次数、上限和涉及的队伍，并保留 S2-3 及原排布。可以从清单直接编辑其中一队，解决冲突后再点击“应用该体力版本”；也可以取消切换。待填分数的队伍同样占用体力，调整阵容时可以继续留空分数。

恢复旧排布时，超体力的阵容会保留并提示调整。如果配置无法载入，程序会保留原始备份并提供导出，不会在启动时用示例覆盖原文件。

这里切换的是体力规则，矩阵期数由排布方案本身记录。S2-3 的 Boss 依次为燎照之骑、封庭械囿、无冠者、天傀劫煞和矩阵奇藏；S2-4 使用对应的 Boss 顺序和暂定血量、分数。

页面下方按矩阵期数展示回路增益和角色强化，内容来自 Nanoka 对应关卡页面，并保留阶段限定说明。体力 +1 的角色常驻显示，回路增益和其余角色强化默认收起，点击标题展开。这些增益供配队时参考，不会自动加到手填分数上。

“Boss 特殊性质”放在角色强化上方，默认收起。展开后可以查看两期共 8 只 Boss，并按名称、简称或性质关键词搜索。天傀劫煞、封庭械囿、无冠者、飞廉之猩、达妮娅和辛吉勒姆已补充特殊性质，对应的 Boss 小窗也会显示相同说明。这些说明供配队时参考，分数仍由自己填写。

## 保存排布

当前排布会自动保存在本机浏览器中，也可以用右上角的“导出 JSON”备份，换电脑或换版本时再导入。

便携版和之前网页调试版的存储是分开的。从旧版迁移时，先在旧版导出 JSON，再到便携版导入。

更新便携版前，请切换到每套需要保留的方案，分别导出 JSON。再右键旧版的系统托盘图标，选择“退出软件”，将新版完整解压到新目录后启动，不要只替换 exe。保存记录与浏览器数据及访问端口有关；新版如果没有显示旧排布，逐个导入备份即可。

## 分数和推算范围

目前支持到 R15，共 75 段 Boss。分数表原有的 42 段保留了原始数据，R9 后三只及 R10—R15 的 33 段按已有规律推算，界面里会标注“推算”。

R4 起的递增系数是每只 Boss 加 0.05，跨轮继续累加。计算方式如下：

```text
n = 5 × (轮次 - 4) + Boss 在该轮的位次（1—5）
递增系数 = 1 + 0.05 × n
普通 Boss 满分 = 19,388,951 / 1200 × 1.25 × 递增系数
矩阵奇藏满分 = 19,388,951 / 1200 × 1.25 × 递增系数 × 1.1 + 1000
```

矩阵奇藏的 1000 分在击杀时单独发放，轴上用斜纹表示。剩余分数包含还没拿到的击杀奖励，奖励区本身没有可以停留的血线。

Boss 详情中的 S2-3 R1—R3 总血量取自原表，R4 起按血量基数乘递增系数推算，单独标注“推算”。R4 起的系数是否完全对应游戏内血量增长，还需要实测。S2-4 的总血量和分数均标注“暂定”。

当前两期按基础全属性抗性 20%、对应高抗属性 40% 显示，40% 的属性会突出显示。暂未加入特殊状态下的抗性变化。

推算部分还没有逐轮实测，游戏内的精确取整方式也暂未确认。有实测差异可以在 [Issues](https://github.com/KazamiSora/wuwa-matrix-planner/issues) 留下轮次、Boss 和分数，方便作者核对。

详细公式和数据来源见 [玩法与计分规则](docs/终焉矩阵调研与计分规则.md)。

## 从源码运行

安装 Node.js 后，在项目目录执行：

```powershell
npm start
```

然后打开 `http://127.0.0.1:4173`。也可以双击 `启动Demo.cmd`，不需要安装额外的 npm 依赖。

几个常用文件：

| 文件 | 内容 |
| --- | --- |
| `config/demo.json` | 初始示例排布 |
| `config/seasons.json` | 赛季目录，指定实际加载的赛季文件 |
| `config/seasons/s2-3.json` | S2-3 的 Boss、抗性、特殊性质、75 波血量与分数、体力、回路和角色强化 |
| `config/seasons/s2-4.json` | S2-4 的 Boss、抗性、特殊性质、75 波暂定血量与分数、体力、回路和角色强化 |
| `config/progression.json` | 高轮次递增规则和推算上限 |
| `data/scores_source.json` | 原表的 42 条记录 |
| `data/scores.json` | 生成 S2-3 赛季文件所用的 75 条基础记录 |

软件实际读取 `config/seasons/` 中的两个 JSON。修改 Boss 顺序、头像路径、体力或增益文本后，刷新测试页面即可生效。实际积分读取 `scoring.waves` 中每波的 `fullPoints` 和 `killBonus`，累计积分会重新计算；`formula` 只作来源说明，不执行其中的文字公式。

每波的 `maxHp` 和 `hpStatus` 控制总血量及其“推算”“暂定”标注，Boss 的 `resistances` 控制各属性抗性，`specialProperties` 保存特殊性质说明。抗性和性质供查看，不会自动改变手填分数。

矩阵增益区域提供“导出赛季JSON”。赛季文件与顶部导出的队伍排布文件是两种配置，顶部“导入JSON”只接收队伍排布。旧的 `config/stamina.json` 与 `data/matrix_content_*.json` 保留为生成配置时的兼容输入，界面不再直接读取它们。

`python tools/generate_season_configs.py` 可以从现有基础数据生成两份赛季文件；已有文件默认保留，只有加 `--force` 才会覆盖。手动修改过赛季 JSON 后请注意保留自己的版本。

### 检查和打包

```powershell
npm test
python -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_release.ps1 -NodeExe "path/to/node.exe"
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test_release.ps1
```

Windows 启动器用 C# 编写，通过系统的 .NET Framework 4 编译器构建。打包脚本会生成便携目录、ZIP 和 SHA-256 校验文件；V0.2.2 附带的 Node.js 版本是 24.22.1。
