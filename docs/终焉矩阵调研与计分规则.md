## 与血线排布有关的玩法

- 终焉矩阵包含稳态协议、奇点扩张。稳态协议最多三支队伍；奇点扩张循环出现敌人，后续轮次增强。
- 每支队伍需要三位共鸣者，并选择增幅回路。积分主要来自对敌人的伤害，不能只按击杀数统计。
- 共鸣者出战消耗疲劳值，两区域独立计算；S2 的危机特勤额外获得一点疲劳值。多模态角色后续应按同一角色的共享使用限制处理，头像条目不能直接等同于独立出战名额。
- 武器与声骸存在占用规则，正式排队功能应保留这类限制的录入位置。
- 本次指定 `/newtower/16` 数据标识为 S2 第三阶段的奇点扩张。该页面的敌人顺序为下表所示；不是把网站所有阶段合成同一关卡。

## 计分公式

令 `p` 为对一只满血 Boss 打掉的血量比例，范围 0—1。令 `H` 为表格公式中的血量基数，`M` 为轮次倍率，`G` 为 R4 起的递增系数，`C` 为宝箱的伤害积分倍率：

```text
伤害积分 = H / 1200 × M × G × C × p
本次得分 = 伤害积分 + 本次完成击杀时的奖励
```

| 轮次 | 普通 Boss 的 H | 宝箱的 H | M |
| --- | ---: | ---: | ---: |
| R1 | 5,612,519 | 6,173,771 | 1.00 |
| R2 | 9,541,514 | 12,756,094 | 1.15 |
| R3 | 19,388,951 | 19,388,951 | 1.25 |
| R4 起（已提供部分） | 19,388,951 | 19,388,951 | 1.25 |

普通 Boss：`C = 1`，击杀奖励为 0。宝箱：`C = 1.1`，击杀奖励为 1000。**1000 分加在所有乘法之后，不参与轮次倍率、1.1 倍或后续递增系数。**

R1—R3 的 `G = 1`。R4 起，从 R4 摩托开始连续编号 `n = 1, 2, 3, …`，每只 Boss 的 `G = 1 + 0.05n`。若 Boss 在该轮的位次为 `j`：

```text
n = 5 × (R - 4) + j
G = 1 + 0.05 × n
```

例如 R4 摩托为 1.05、R4 宝箱为 1.25、R5 摩托为 1.30。这是按连续波次增加，不会在新一轮重置。该关系已核对原表后段全部 27 条记录，程序按同一关系延伸到 R15。

R4 起原表将递增项放在乘式末尾。仅凭这一写法，不能分清该增长在游戏中属于实际血量增长还是伤害兑换积分系数变化。模型保留公式原义，以血量百分比和整只伤害积分换算。更高轮次的推算总血量使用 H×G；这属于对公式的解释，不标为游戏内实测血量。原表记录无推算标记，新增记录标记 estimated: true。

### 已核对示例

```text
R1 摩托：5612519 / 1200 = 4677.099166666667
R1 宝箱：6173771 / 1200 × 1.1 + 1000 = 6659.290083333334
R2 摩托：9541514 / 1200 × 1.15 = 9143.950916666665
R4 宝箱：19388951 / 1200 × 1.25 × 1.1 × 1.25 + 1000
        = 28770.632942708333
```

## 血线换算时的边界

- 队伍从剩余血量 `a` 打到 `b`，伤害积分为该 Boss 的整只伤害积分乘以 `a-b`。血量比例统一使用 0—1。
- 宝箱的 1000 分归属于完成击杀的队伍，打残宝箱不会提前得到奖励。
- 宝箱击杀奖励造成 1000 分跳点。若目标落在跳点内，程序应显示必须击杀及超出的积分，不应给出一个不存在的精确血线。
- 源表未使用取整函数，当前保留完整小数。游戏是否逐伤害、逐队或总计取整仍需实测，显示的小数位不能代替实际取整规则。
- 已提供 `score_core.py` 的基础换算函数，以及 JavaScript 血线排布 Demo：支持三人选角、录入分数、拖动色条、查看起止血量和 JSON 导入导出。已支持按期体力限制、快捷组队、单轴拖动排序和目标总分标记；尚未加入自动最优排队。
